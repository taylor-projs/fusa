# 双寄存器（bit / ~bit）SEU 处理机制

> 对象：`rtl/hang_prot_core.sv`
> 问题：设计里大量寄存器采用双副本存储（原值 + 反码），如果发现 `bit != ~bit_n`（副本不一致），IP 功能怎么往下走？

## 结论（一句话）

"bit != ~bit_n" 不是故障即停机，而是 **"fail-visible + 就地自愈 + 强制提前上报"**：检测到不一致的那一拍，功能照常往下走，但走的方向被故意掰向"可见、偏早、绝不会静默失效"。

## 按寄存器类别分解

### 1. 计数器类（cnt / otd / dlv）—— 故障强制"立刻开火"

最关键的一类。副本不一致信号 `*_f` 直接 OR 进 fire 条件（`hang_prot_core.sv:309-310`、`396-399`）：

```systemverilog
rd_r2a_to = ena_mon && (rd_r2a_to_a | rd_r2a_to_b | rd_cnt_a_f);
```

即：计数器副本一旦不一致，**不等真的超时，当拍就把 esm_err 拉起来**。

理由：损坏的计数器只有两个危险方向——报得太晚或永远不报，所以干脆往"偏早"方向错。同时：

- **双比较器**（A 路用原值、B 路用反码副本）**OR** 进 fire，任一健康副本满足条件都能触发；
- A/B 不一致（`*_cf`）单独作为 esm_fault 上报，不混进 esm_err。

**功能怎么继续：**

- 每周期重写的计数器（如 `rd_cnt_a`）：反码副本永远从原值重新推导（`rd_cnt_a_n <= ~(rd_cnt_a + 16'd1)`，`315-326` 行），单比特翻转**下一拍自动同步回来**——这就是自愈，不需要停下来修复。
- 只在握手事件时更新的寄存器（如 otd）：不一致会一直保持 fire，逼 SW 介入（用 `to_clear` 把两份副本一起清零重同步）。

### 2. 阈值类（thr）—— 回退到复位值，绝不静默关闭

`hang_prot_core.sv:253-256`：

```systemverilog
wire        thr_a_fault = (thr_a_qn != ~thr_a_q);
wire [15:0] thr_a_eff   = thr_a_fault ? REQ2ACCEPT_RST : thr_a_q;
```

不一致时 `esm_fault` 上报，同时**有效阈值退回非零的复位默认值**。监控继续跑，只是暂时用默认门限——损坏的阈值永远不可能把检查关掉（退到 0）。

### 3. 使能码（ena_q）—— 多数表决，模糊态保持 ON

4'b1111 / 4'b0000 汉明距离 4 编码 + 多数判决（`209-234` 行）：

- 任何偏离码字的值都报 `esm_fault`；
- 下一拍把多数判决出的干净码字写回（自愈）；
- 两比特翻转（ones == 2）方向不明时**保持监控 ON**——宁可误报不可漏报；
- 判决用的是 `ena_mon`（当拍生效），所以 SEU 那一拍监控行为也是对的。

### 4. 状态类（sticky status）—— 自愈为置位

`474-477` 行的 `st_*` 不一致信号被 OR 进置位路径（`493` 行等）：被 SEU 清掉的报错位会被**重新置回 1 并重报**，同时该不一致本身也进 esm_fault。

### 5. 上报通道本身也是双轨

- `esm_err / esm_err_n`、`esm_fault / esm_fault_n` 成对输出（`591-592`、`566` 行），传输线上的翻转由 ESM 侧检测；
- `esm_fault`（监控器自身坏了）与 `esm_err`（真超时）**故意走独立事件、独立 ESM 组**——坏掉的监控器绝不和真实的总线超时混淆；
- `fu_src`（`579-586` 行）sticky 记录是哪一路一致性检查炸了；
- `fu_selftest` 提供"有 fault 无 source"的自检图案来验证这条链路本身。

## 串起来的完整闭环

检测到不一致后 IP 的行为链条：

1. **当拍**：fire（计数器类）或继续监控（阈值/使能类用回退值），`esm_fault` 置位 → 独立 ESM 中断；
2. **下一拍**：可自愈的寄存器（计数器、使能码、状态位）自动重同步；
3. **SW 侧**：ESM 服务程序读 `fu_src` 定位源头 → 处理（复位/清计数）→ `r2a_w1c`/`r2r_w1c` 清报错、`to_clear` 重同步计数器、`fu_w1c` 清故障（仍有 live source 会立刻重置，T6 语义）；
4. **兜底**：两份副本同时翻转的共模残余，靠周期性 `selftest_key` / `fu_selftest` + 上电端到端事务测试覆盖（`87-89` 行注释明说了）。

## 设计意图总结

发现 `bit != ~bit_n` 时功能不是"停"，而是"掰方向"——所有故障路径都收敛到"更早、更显眼地上报"，监控逻辑本身用副本/回退值/多数判决继续运行，能自愈的自愈，自愈不了的靠 SW 清除后重同步。这正是 TI Hercules CCM 式反相副本比较的设计意图：**监控器的故障本身也必须是被监控、被上报的事件**。
